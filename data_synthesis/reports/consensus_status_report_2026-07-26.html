Consensus Decoding for Simultaneous Speech Translation — Status Report

Haoling Pu — July 26, 2026. Prepared as a handoff document. All numbers are trained-model eval unless marked "synthesis-time".

1. Executive summary

  • What this is. Consensus decoding is our reference-free, future-blind data-synthesis policy for simultaneous en→zh speech translation on GigaSpeech: two base LLMs sample plausible English continuations ("futures"), an instruct LLM supplies Chinese next-token distributions, and a token is committed only when the futures agree on it. Synthesized trajectories are then used to LoRA-finetune a Qwen3-Omni streaming model (the "infinisst-omni" checkpoint family), evaluated with simuleval on ACL 6060 dev and Simul-tst-COMMON.
  • Current best system: consensus-top5-axis5 — 5 directed "narrative axis" futures × ~4 samples = 20 futures, strict 100% token intersection, decoded on the old ASR (asr_filtered) with MetricX-QE filtering. It is the ref-free COMET leader on ACL 6060 (0.808–0.817 at seg1920–3840) and the baseline every experiment is compared against.
  • Key positive finding: directed diversity is the lever. 20 directed futures beat 200 undirected ones on both COMET and BLEU at every latency; loosening the commit rule (soft-vote) and brute-force scaling (100 futures) do not help.
  • Central open problem: consensus trails the reference-based hibiki/word-align system by ~6.5–8.3 BLEU at matched latency with COMET tied. We proved the gap is real (it survives monotonic references) and traced the root cause: the voting machinery systematically picks formal written Chinese (因此 / 将 / 与) where the reference uses plain spoken Chinese (所以 / 把 / 和). Every fix tried so far failed. In one sentence each — the change made on top of the original consensus decoder:
    • Post-edit, 3 variants (§5.2): decoder unchanged; an LLM rewrites its committed output afterwards — as a strict minimal edit, a free re-translation, or a free polish. All three scored worse than not editing.
    • Anchor-and-veto (§5.5): the futures no longer choose the wording — a plain greedy translation of only the observed source ("anchor") writes the text, and the futures are demoted to only deciding how many of its tokens are safe to commit. Won the synthesis-time smoke, but the trained model degenerated (over-generation on non-speech audio).
    • Hybrid (§5.5): the unchanged consensus vote decides when and how many tokens to commit; the anchor's greedy text supplies what those tokens say. +0.15 char-BLEU — proves the anchor's smoke win was timing, not wording.
    • Best-of-N selection, 2 variants (§5.6): decoder unchanged; decode the same 40k utterances five ways and, per utterance, train on whichever version is closest to the reference. +10.9 oracle BLEU at synthesis time became ~0 after training.
    • Present-ranked winner (§5.7): keep the agreement gate unchanged, but pick among the surviving tokens using the no-future ("present") distribution instead of the future-averaged score. −2.15; the strict gate leaves only 1–2 survivors, so the winner rule has no freedom.
    • Present-proposes / futures-verify (§5.8) — PENDING: flip who authors the candidates — the no-future distribution proposes its top-6 tokens, and the futures only approve or veto each one by majority vote. Smoke decode finished (500/500); the paired analysis has not been run yet.
  • Note on ASR data: we also tried re-transcribing the audio with a new Qwen-ASR, but it regressed trained eval (−4–6 BLEU / −0.05 COMET) and no fix recovered it, so it was abandoned — everything in this report uses the old ASR.
  • Where a new person should start: Section 7 lists the open threads, and Section 6 lists everything that is conclusively dead and should not be rerun.

2.4 Two evaluation ground rules (hard-won, do not violate)

  • Synthesis-time BLEU does not predict trained-model BLEU. Never rank configs by synthesis-time scores; only trained eval counts. (Extended in §5.6: even per-utterance oracle selection worth +10.9 synthesis BLEU transferred to ~0 trained BLEU.)
  • Rank by COMET, not BLEU. BLEU favors surface-form matches; EAST-even leads BLEU (~47) with mediocre COMET (~0.79), while consensus leads ref-free COMET at lower BLEU. Ignore BLEU gaps ≤2–3 when COMET is tied. Caveat: vs hibiki specifically, COMET is tied, not won — that is exactly the open problem of §5.

2.5 How consensus decoding works — the full data flow, step by step

Everything happens at synthesis time, on text: we take an ASR transcript, pretend it arrives incrementally in ~960 ms chunks, and use the decoder below to produce a trajectory — a translation broken into per-chunk committed pieces (an interleaved READ/WRITE recipe). The trained model then learns to imitate that trajectory from real streaming audio.

The inner decode loop (runs per utterance):

 ┌─────────►[1 READ]──►[2 SAMPLE 20 futures]──►[3 TRANSLATE ×20]◄────┐
 │                                                    │              │
 │  no agreement                                 [4 AGREE?]          │
 └────────────────────────────────────────────────────┤              │
                                                  yes ▼              │
                                            [5 WRITE one token]──────┘
  1. READ — reveal the next ~960 ms chunk of the ASR transcript; the observed source grows.
  2. SAMPLE 20 futures — the two base LLMs each imagine plausible English continuations of the observed source (5 directed axes × ~4 samples = 20). The future decoding window controls how many recent source chunks the samplers see (flagship: win1 = the current chunk only).
  3. TRANSLATE 20 times — the probe (Qwen3-30B, temperature 0) is asked for the next Chinese token 20 times, once per future: "observed source + future #i, committed prefix so far → next-token distribution".
  4. AGREE? — the agreement gate: a token is eligible only if it appears in the top-6 candidates of all 20 distributions (flagship: 100% intersection, top_k=6, min_p=0).
  5. WRITE — commit the winner (highest average probability across the 20 futures), append it to the Chinese prefix, and go back to step 3 for the next token. When no token passes the gate → stop writing, go back to step 1 and READ more source. When the transcript is exhausted → finish with a free greedy completion.

The outer synthesis → training pipeline (runs once per experiment):

 40k utterances (ASR + LLM reference)
   → consensus decode (loop above)
   → period-fix
   → QE filter (MetricX ≤ 3.0; ~18.6k survive)
   → length-ratio filter (0.7–1.5 × reference)
   → sample 12,500 → SWIFT training format
   → LoRA train Qwen3-Omni (~1 h)
   → streaming inference + scoring (BLEU · COMET · latency, vs baseline + hibiki)

Key knobs, in plain terms:

  • Future decoding window: how many of the most recent source chunks the base samplers are shown when they write hypothetical continuations (flagship: win1, i.e. the current chunk only).
  • Agreement (the gate + the winner): a Chinese token is only eligible if it appears in the top-6 candidates under every one of the 20 futures (the "-sv" soft-vote variant relaxed this to 75% of futures and lost 2–4 BLEU); among eligible tokens, the winner is the one with the highest average probability across futures.
  • QE filter threshold: MetricX quality-estimation score (lower = better), computed per aligned sentence; an utterance is kept only if its worst sentence is ≤ 3.0. This is the filter that prevented the catastrophic BLEU-6.9 collapse on unfiltered data (§4.2).
  • Length-ratio filter: output length must be 0.7–1.5× the frozen reference — a cheap guard against dropped content and the over-generation failure mode that later sank the anchor method.

A worked example (real case from the smoke logs). The transcript revealed so far ends with "…this work is inevitably both". The 20 futures disagree about what comes next — some continue "…both tedious and useless", others "…both a burden and a joy". Under every future, the safe Chinese adverb 不可避免地 ("inevitably") is a top candidate → it passes the 100% gate and is committed. But the noun reading 双重性 ("duality", treating "both" as a noun and ending the sentence) is only plausible under futures where the sentence stops — it fails the gate, so the decoder stops writing and READs more source. Two chunks later, "tedious and useless" actually arrives and it commits 既单调又无用. A plain translator without the vote (our "free re-translation" baseline) committed 双重性。 and closed the sentence — exactly the early-commitment mistake the agreement gate exists to prevent.

4. What actually improves consensus

4.1 5-axis directed futures vs soft-vote vs scaling (all trained end-to-end)

Question: starting from the naive baseline (200 undirected futures, hard token intersection), which lever improves trained quality? Answer: directed diversity wins; the other two fail.

  • Soft-vote is a clean negative: loosening the 100% intersection to a 75% majority loses 2–4 BLEU — the gap is not "too conservative".

4.2 QE filtering

MetricX-QE-MAX filtering is the single biggest guard against catastrophic collapse: on an unfiltered new-ASR control, seg960 collapsed to BLEU 6.9; QE filtering alone restored it to ~30 (+23 BLEU). Keep it on always.

5. The ~7 BLEU gap vs hibiki (the main research thread)

5.1 The phenomenon

Consensus trails the ref-based hibiki/word-align checkpoint by ~6–8 BLEU at matched latency with COMET tied (consensus even edges COMET at seg2880/3840 on Simul-tst). Consensus is the only policy that is both reference-free and future-blind; the question the whole line asks is how much of the deficit is that honest constraint vs something fixable.

5.2 Post-edit — triple negative (2026-06)

Can an LLM post-edit recover BLEU? No. Synthesis-time char-BLEU vs frozen reference (5-case smoke): raw consensus 56.7; strict minimal-edit polish 52.4 (injects bad punctuation); free re-translation 46.2 (early commitment — e.g. committed "双重性。" and closed the sentence after seeing "...inevitably both"); free polish 12.8 (hallucination, length ratio 2.36×). Together with the soft-vote trained negative: loose edits reintroduce anticipation, strict edits add noise — consensus's committed text is already at its fluency frontier.

5.3 Is the gap a reference-style artifact? — No (2026-07-11)

Re-scored all zh checkpoints on Simul-tst-COMMON (monotonic, interpreter-style references). The hibiki lead persists unchanged: 6.5–8.3 BLEU at matched latency, COMET tied. The gap is real, not offline-reordering bias. (Bonus finding: EAST-even kept its BLEU lead there while posting the worst COMET — the rank-by-COMET rule survives on an independent test set.)

5.4 Root cause: register forensics (2026-07-11)

Word-level forensics located exactly where the BLEU lives. Headline: the SAME Qwen3-30B model at temperature 0 produces the frozen reference (whole-doc greedy), hibiki's targets (per-sub-sentence greedy) and consensus's token distributions — the gap is purely the decode procedure.

  • Consensus training targets score only 59 char-BLEU vs the frozen reference (4-gram overlap 0.48) — the two checkpoint families were trained toward surface distributions ~40 BLEU apart; the test-set gap is that divergence's shadow.
  • The deficit compounds with n-gram order: −4.7% char 1-gram recall but −19.2% at 4-grams — sparse word swaps, content preserved (why COMET ties).
  • The swaps are a systematic spoken→written register shift: 所以→因此 (×36), 和→与, 把→将, 可以→能够, 去→前往, …; consensus never says 但是.
  • Mechanism: formal connectives survive under more sampled continuations, so the future-intersection gate and the future-averaged winner rule both amplify them (voted body has 3× the 因此 of the same utterances' free-completion tails); the 5-axis hints skew conditioning formal; the incremental prefix drifts off the model's greedy manifold.

5.5 Anchor-and-veto — smoke win, trained failure (2026-07-12 → 07-19)

Design: invert the roles — a greedy "anchor" continuation conditioned only on observed source (using hibiki's exact sub-sentence translation prompt) proposes the wording; futures only veto how far to commit (min-p gate under 100% of futures). Code: consensus_decoding_anchor.py.

  • Smoke (500 utts, variants A–D): strict gate A (min-p 0.05 / top-k 5 / voters 1.0) won +6.98 paired char-BLEU (67.25 vs 60.27), register normalized, quality monotone in gate strictness. Caveat: LAAL +1.8. Promoted to a full anchor_40k production decode + training run.
  • Trained verdict: NEGATIVE. BLEU 14.2/25.3/29.3/29.9 vs baseline 27.5/32.1/34.1/34.2 on Simul-tst. Root cause is degenerate over-generation, not waiting: +19% chars, onomatopoeia floods on non-speech audio (one talk emitted 8,456 chars of "呼！"; rep-4gram 0.115 vs baseline 0.043). The consensus vote's cross-future agreement was the trained model's built-in silence brake on contentless audio; the anchor removed it. The 12–35 s LAAL numbers are a scoring-alignment artifact of the floods.
  • Hybrid follow-up (consensus decides WHEN, anchor decides WHAT): NEGATIVE — +0.15 paired char-BLEU (gate was ≥ +4). This falsifies the wording hypothesis: config A's smoke gain came from its timing (waiting longer), not the anchor's wording. Both halves of anchor-and-veto are individually falsified; method closed.

5.6 Reference-selected best-of-N — closed negative (2026-07-19)

Design: keep the decoder ref-free but let selection use the reference: per utterance, pick the best of 5 complete 40k decodes (flagship, fut100, n100, softvote, anchor) by char-BLEU vs the frozen reference, QE- and length-guarded. Oracle headroom gate passed spectacularly: +10.95 char-BLEU (59.2 → 70.2).

  • bestof5 trained: ≈0. The +10.9 oracle became ~0 trained BLEU at useful latencies (only anomaly: tst seg960 blow-up from anchor-pool timing contamination).
  • bestof4 (anchor excluded) trained: negative in every cell, with its own timing blow-up (tst seg1920 YAAL 33 s) — per-utterance style switching between pools destabilizes the policy by itself.
  • Conclusion: per-utterance selection conclusively does not transfer to training; what training absorbs is a systematic distribution shift, not per-example picking. This extends "synthesis BLEU is not predictive" from config ranking to selection.

5.7 Present-ranked winner — negative, but diagnostic (2026-07-19)

Design: keep the flagship strict gate; re-rank the gate's surviving tokens by the present (no-future) distribution instead of the future-averaged score. Fully ref-free. Code: experimental/consensus_decoding_present_rank.py.

Result: −2.15 paired char-BLEU on smoke500, hygiene perfectly clean, register markers statistically unmoved. Diagnosis: the strict top-6 intersection typically leaves only 1–2 eligible tokens — the winner rule has no freedom. The register bias enters at the GATE (future-conditioned candidate sets), not the winner rule. Prompt forensics also ruled out prompt misalignment: the probe and reference prompts are near-identical; the appended future text in [INPUT] is the shift.

5.8 Present-proposes / futures-verify — IN FLIGHT (the one open experiment)

Design (register fix #3): invert who authors the candidate set — the present distribution PROPOSES its top-6 (the canonical-register manifold), futures only VERIFY (a proposal survives iff it appears in the top-6 of ≥15/20 future-conditioned distributions); winner = argmax present probability among survivors. Not a rerun of soft-vote: soft-vote relaxed the threshold over the same futures-proposed universe; here the proposal universe itself moves. Code: experimental/consensus_decoding_present_propose.py, smoke job 9370692.

Status as of 2026-07-26: the smoke decode is complete (500/500 per-utterance JSONs in consensus_decoding_prod/present_propose_smoke500/task_00/per_utt/) but the paired analysis has not been run yet. Next action: run analyze_present_rank_smoke.py (evaluation env, needs jieba) paired against the J_40k per-utt JSONs. Gates: proceed iff paired char-BLEU ≥ +2 AND hygiene clean (length-ratio tail, rep-4gram, LAAL family of J_40k); leading indicator = register markers move toward the reference profile (因此 9.9→~6, 将 63.8→~40, 把 35.3→~55 per 10k). If killed with markers unmoved, the register bias is upstream of the candidate sets entirely and the decode-time family is exhausted → accept rank-by-COMET as the paper story.
